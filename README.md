# LungAI — Lung CT Image Classification

A Streamlit inference application for a four-class CNN exported to ONNX Runtime.

> **Important:** This is an educational/research prototype, not a medical device. It is not validated for diagnosis, screening, treatment, or clinical decision-making. A model score is not a calibrated clinical probability.

## Project layout

```text
LungAI/
├── app.py
├── train_lung_cancer.py
├── requirements.txt
├── requirements-training.txt
├── .streamlit/
│   └── config.toml
├── dataset/                       # training data; do not deploy this folder
│   ├── train/
│   │   ├── adenocarcinoma.../
│   │   ├── large.cell.../
│   │   ├── normal/
│   │   └── squamous.cell.../
│   └── test/                      # independent test images, same class folders
└── models/
    ├── lung_cancer_model.onnx     # generated by training script
    ├── lung_cancer_model.keras    # generated by training script
    ├── best_lung_cancer.keras     # generated by training script
    └── metadata.json              # generated by training script
```

The training script also supports a single directory containing class subfolders. In that case, it creates disjoint, stratified train/validation/test partitions (70/15/15). Do not point the test path to the same directory as the training path.

## 1. Train and export the model

Use a fresh Python 3.11 environment for the training/export stack. The supplied notebook's ONNX conversion output reports that `np.cast` was removed in NumPy 2.x, so `requirements-training.txt` deliberately pins NumPy to 1.26.4 and uses a compatible TensorFlow/tf2onnx set.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
# source .venv/bin/activate

python -m pip install --upgrade pip
pip install -r requirements-training.txt
python train_lung_cancer.py --data-root "path/to/Data/Data" --output-dir models --epochs 50
```

For the preferred directory structure, `--data-root` must contain `train/` and (ideally) a genuinely separate `test/` directory. If `test/` is absent, the script will generate three stratified splits from the available class-folder directory.

The script saves:

- `models/lung_cancer_model.keras`
- `models/best_lung_cancer.keras`
- `models/lung_cancer_model.onnx` (after conversion and a smoke test)
- `models/metadata.json` (class order and preprocessing settings)
- `models/classification_report.json`
- `models/confusion_matrix.csv`
- `models/training_curves.png`

If ONNX export fails, do not deploy yet. The Keras model may still have been saved; fix the conversion environment and export again.

## 2. Run Streamlit locally

Install only the lighter inference dependencies:

```bash
pip install -r requirements.txt
streamlit run app.py
```

Place the ONNX model and metadata at `models/lung_cancer_model.onnx` and `models/metadata.json`. The app also checks for the ONNX file and metadata in the project root as a fallback.

## 3. Deploy on Streamlit Community Cloud

1. Push `app.py`, `requirements.txt`, `.streamlit/config.toml`, and the `models/` inference artifacts to GitHub.
2. Do not upload the training dataset or the training environment.
3. Create a Streamlit Community Cloud app pointing to `app.py`.
4. Confirm the deployed app can load `models/lung_cancer_model.onnx` and `models/metadata.json`.

If the ONNX file is too large for your Git workflow, use Git LFS or an approved model-artifact store and adjust the model path. Do not commit the full image dataset to the deployment repository.

## Corrections made compared with the supplied files

- The notebook assigned `test_dir` to the same `train` directory. The new training script prevents that error and uses an independent test folder where available; otherwise it creates disjoint stratified splits.
- The original app hardcoded class labels. The training script now writes class names in exact output-index order to `metadata.json`; the app reads that metadata.
- The original CNN used `Flatten()` and a large dense layer (~4.7 million parameters). The revised architecture uses `GlobalAveragePooling2D()` to reduce parameter count.
- Training now includes class weights, early stopping, best-checkpoint saving, and learning-rate reduction.
- Image preprocessing in the app matches the training pipeline: RGB, 150×150 by default, nearest-neighbour resize, float32, and division by 255.
- The old hardcoded prevalence/survival claims and clinical action recommendations have been removed because the supplied notebook does not establish those facts.
- The app validates file size, image readability, ONNX input/output dimensions, and the consistency of model outputs with the metadata.

## Validation limitation

The uploaded files did not include the trained ONNX model or the underlying CT image dataset. Therefore the app and training script can be statically checked here, but actual training metrics, ONNX conversion, and end-to-end prediction must be verified in your environment with the dataset and generated model artifacts.
